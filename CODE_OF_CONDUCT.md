# Code of conduct

This is a small, single-maintainer open-source project about writing books with
local language models. The point of this file is that nobody has to guess how to
behave here, and that disagreements about code, prompts or prose never become
personal.

## Expected behaviour

- **Criticise the work, not the person.** "This prompt template is fragile
  because…" is welcome; "you clearly don't understand prompting" is not.
- **Assume good faith and be specific.** Say what you ran, what you expected and
  what happened. A config snippet and a model name solve most mysteries.
- **Respect different hardware, models and tastes.** A 12 GB card, a hosted API
  and a CPU-only laptop are all valid setups here; so is preferring a different
  model's prose.
- **Keep reports and examples safe for a public repository.** No API keys, no
  personal data, and warn before pasting anything explicit that a model wrote.
  This project deliberately supports uncensored models; that is not a licence to
  post distressing content in an issue.
- **Accept a "no".** Not every feature fits the project's scope; a clear
  explanation beats an argument.

## Unacceptable behaviour

- Harassment, insults, slurs, or discriminatory comments about a person's
  identity, background or ability.
- Sexual attention or imagery directed at anyone, and unwelcome contact.
- Publishing someone's private information (address, email, employer, logs that
  identify them) without permission.
- Sustained disruption: reopening settled decisions to derail a thread,
  spamming issues or pull requests, or demanding free support.
- Plagiarism in contributions: code, prose or seeds copied without their licence
  and attribution.

## Scope

This applies in the repository's issues, pull requests, discussions, commit
messages and reviews, and anywhere someone is representing the project.

## Reporting and enforcement

Report a problem by opening an issue asking the maintainer for a private channel,
or contact the maintainer directly through their GitHub profile. Reports are read
by the maintainer only. Please say what happened, where, and what you would like
to happen next.

The maintainer will:

- reply as soon as reasonably possible, and keep the report confidential;
- decide whether a comment or contribution should be edited, hidden or reverted,
  and whether an apology, a warning, or a temporary or permanent block from the
  repository is the right response;
- say what was decided, to the reporter and to the person reported, unless doing
  so would expose the reporter.

Enforcement applies equally to the maintainer: if the maintainer is the problem,
say so, and a report about them can be sent to any other contributor they have
worked with on this repository.

This file is written for this project; it is not a copy of the Contributor
Covenant.
